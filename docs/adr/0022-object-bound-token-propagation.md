# ADR 0022: Object-bound credential redemption and signed authority

Status: Accepted for P2 application/protocol-adapter integration. No live token endpoint is enabled by this change.

The token context reuses grant-domain tuple attenuation and the current registration projection instead of implementing a second RAR policy engine. Credential authentication returns only an object-bound presence flag. Client, exact tenant/issuer/resource, sender binding, redirect and S256 possession checks precede loading protected object identifiers. Authenticated replay still commits lineage revocation before any grant/object payload is loaded.

An object credential can be redeemed only with approved PAR workflow and immutable presentation provenance. Its historical revision, current durable grant and credential ceiling must all be present, bound to the same context, and valid under current resource/client type/action registrations. Omitted details preserve the intersection of those three ceilings. Explicit empty, additional identifiers/actions, tuple recombination and unknown types/actions fail. Scope-only proof fixtures cannot discard object authority; missing or partial object state cannot fall back to a scope token.

The application assigns the effective ceiling to access claims. The existing Transit signer maps it into the standard `authorization_details` JWT claim; the Fosite service handler emits the same standard token-response array. Only `type`, one exact `locations` audience, opaque `identifier` and registered `actions` are emitted. No consent labels or raw stored envelope is copied into tokens. Wire grammar remains bounded and duplicate-sensitive. Structural parsing happens before credential redemption; current profile validation happens after possession. The signer and response codec enforce the same 32 KiB serialized detail bound.

Issuance persistence records the assigned ceiling atomically with consume/lineage/audit. A refresh successor stores that same narrowed ceiling, so later omission cannot recover the predecessor's discarded objects/actions. Commit checks pin claims to the loaded credential, revision and current grant, including exact principal/client/resource/binding, scope/tuple subsets, expiry and current policy/resource/client access lifetime. Current resource scope vocabulary and required sender binding are rechecked under the tenant coordination lock.

`tests/contract/object_issuance_test.go` covers complete typed redemption, both credential kinds, object/action narrowing, omission, lost authority, foreign ceilings, registration loss, effects ordering and failed commit. `tests/integration/object_token_test.go` exercises actual PAR approval through the PostgreSQL resource adapter, Fosite service hooks, non-exportable local Transit signing, signature verification, identical response/JWT/persisted ceilings, object expansion denial without consume, and replay revocation. Existing P0/P1 proof fixtures now include real current resource/client/type registrations rather than bypassing registration checks. No dependency or tool is added.

The resource owner's current ACL is a separate authority from a durable grant ceiling. Signed details alone do not authorize payload access or guarantee immediate revocation. Authoritative status/current-permission enforcement, public endpoints, initial consent-authorized refresh families, keyed credential hashing, transaction-owned signing-key selection, OIDC/opaque/machine features and the BFF/SDK exit demonstration remain P2 gates. Scope-only fixtures remain internal proof scaffolding, not an optional production deployment profile.

Reference: [RFC 9396 token request/response and resource-server claims](https://www.rfc-editor.org/rfc/rfc9396.html#section-6).
