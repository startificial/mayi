# ADR 0006: External PostgreSQL and P1 operator boundaries

Status: Accepted · 2026-10-17

Mayi runs as a standalone Go process against operator-supplied PostgreSQL. It owns a fixed `mayi` schema, not the customer's database, application tables or identity-provider tables. A second PostgreSQL instance is optional. Provider compatibility is an evidence claim: P1 tests PostgreSQL 17.11 directly, not Supabase, Neon or third-party poolers. Reusing existing user accounts requires a separate authentication integration in P2.

The migration connection uses a schema owner. The server and outbox worker use a separate non-owner role without superuser, role/database creation, RLS bypass, schema creation, audit mutation or migration-history mutation privileges. The DBA creates these roles; Mayi does not provision database users or borrow an application's privileged credentials. `migrate` and `provision` are explicit local operator commands, never HTTP endpoints or automatic startup effects. Source/checksum migration history, an advisory transaction lock, and additive migrations reject unknown or modified schemas. The P0 fixture schema is not automatically adopted.

Every runtime physical connection checks the role, schema history, ownership and forced RLS. Transaction-local tenant settings, explicit tenant predicates and composite relationships apply to administrative operations, keys, public projections and worker leases. Tenant identifiers and issuers are immutable. A server's public origin comes from validated configuration; request Host and proxy headers cannot select authority. P1 binds to loopback behind a locally trusted HTTPS proxy. The default database transport requires verified TLS, including hostname verification. The development exception permits plaintext only to loopback or a local Unix socket.

P1 management credentials are high-entropy operator-generated bearer secrets represented by SHA-256 digests in trusted configuration. Each credential grants explicit actions to exactly one tenant. The inbound adapter authenticates; the administration service checks actor, issuer, tenant and action before any protected read or mutation. No cookie, query-token or browser-origin administration is accepted. These bootstrap credentials require a restart for rotation and are not the future OAuth admin-token or step-up implementation. Provision/configuration access remains a trusted operator capability; a tenant admin cannot edit it through this API.

Public signing keys are verified against explicit, non-exportable ES256 Transit versions. Publication and activation are separate audited transactions. The initial key of a newly created tenant may activate immediately. Subsequent activation requires at least 60 seconds of publication; JWKS uses `no-store`, and old public keys remain indefinitely in P1. There is no retirement endpoint or automatic Transit minimum-version change. Operators must publish while the public route is reachable, roll compatible signer configuration to every replica, verify JWKS, wait the lead time and only then activate. Persistence records publication time, not proof that an external client fetched it. Ring version resolution is a signing boundary; P2's transactional issuance composition must avoid nested acquisitions from a saturated issuance pool and retain final policy/key checks.

Public metadata at RFC 8414's path-derived location is explicitly a P1 foundation preview. It contains no token/authorization endpoint and advertises no grants or scopes. It is not a conformant AS configuration yet: RFC 8414 requires a token endpoint except for an implicit-only server. The OpenID configuration endpoint remains absent until P2 can enforce its required OP behavior. Do not advertise fictional endpoints or treat a metadata fixture as conformance. DISC-1/2 remain partial/planned.

Security-event insertion atomically enqueues an outbox row. Audit records are append-only to the application; outbox leases use attempt counters to fence stale acknowledgements and remain retryable after a worker crash. The worker emits credential-free JSON for an operator-owned collector. Delivery is at least once; downstream deduplication uses issuer/tenant/event ID. A successful write to stdout is not durable receipt by a remote SIEM. Durable remote transports, tenant retention, external audit anchors, login/admin step-up, rate limits, full metrics/tracing, HA and restore verification remain later delivery work.
